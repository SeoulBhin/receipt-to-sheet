# receipt-to-sheet

영수증 파일 → 네가 직접 읽어 `out/<이름>/receipts.json` 작성 → `python check.py out/<이름> <입력 폴더>` 가 검산하고 `out/<이름>/<이름>.xlsx` 를 만든다.
너는 **읽고 옮겨 적기만** 한다. 계산이 맞는지는 check.py 가 본다.

## 순서

1. 입력 폴더의 파일을 전부 찾는다(`.png .jpg .jpeg .pdf`). 한 장도 빼먹지 않는다.
2. 파일을 하나씩 Read 로 열어 **보이는 그대로** 옮긴다. 아래 스키마로 `out/<이름>/receipts.json` 을 쓴다.
3. `python check.py out/<이름> <입력 폴더>` 를 돌린다.
4. `✗`(형식 오류)가 나오면 receipts.json 을 고치고 3으로. **형식 오류가 0건이 될 때까지 끝내지 않는다.**
5. `?`(확인 필요)로 나온 건은 원본을 **한 번 더 열어 본다.**
   - 내가 잘못 읽었으면 고친다.
   - 원본에 정말 그렇게 적혀 있으면 **그대로 둔다.** 합을 맞추려고 숫자를 바꾸지 않는다. 원본이 틀린 걸 사람이 봐야 한다.
6. 사용자에게 엑셀 경로, 통과·확인 필요 건수, 확인 필요 사유를 짧게 알린다.

- `check.py`·`test_check.py`·`verify.py` 는 **절대 고치지 않는다.** 검사기가 틀렸다고 보이면 고치지 말고 멈춘 뒤, 어떤 입력에서 왜 틀렸는지 사용자에게 보고한다.
- 입력 폴더의 원본 파일은 고치거나 옮기지 않는다.

## 읽는 규칙

- **추측하지 않는다.** 흐리거나 가려져서 숫자를 확신할 수 없으면 그 건은 `"status": "확인 필요"` 로 두고 `note` 에 이유를 쓴다. 안 보이는 금액을 다른 칸에서 거꾸로 계산해 채우지 않는다. 확신 못 하는 칸은 null.
- 금액은 원 단위 정수. `"14,000원"` 이 아니라 `14000`.
- 날짜는 `YYYY-MM-DD`. 영수증에 `26.10.05` 처럼 줄여 적혀 있으면 2026-10-05 로 바꾼다(연도가 두 자리면 20xx).
- 공급가액·부가세가 따로 적혀 있지 않은 영수증(택시·간이영수증 등)은 둘 다 null. 직접 계산해 넣지 않는다.
- 품목 금액은 원본에 적힌 대로. 카드 영수증은 보통 부가세 포함 금액, 청구서는 공급가액 기준이다 — 어느 쪽이든 원본 그대로.
- `payment` 는 `카드`·`현금`·`계좌이체`·`기타` 중 하나. 법인카드·신용카드·자동결제(카드)는 `카드`, 입금 계좌 안내는 `계좌이체`.
- 같은 영수증을 두 번 찍은 것 같아도 **둘 다 기록한다.** 중복 판정은 check.py 가 한다.
- 가맹점 이름은 영수증 맨 위 상호 그대로(지점명 포함).

## 스키마

파일마다 한 줄. 값은 형식 설명용 예시다.

```json
[
  {
    "file": "samples/파일이름.png",
    "date": "2026-01-31",
    "merchant": "상호",
    "items": [{"name": "품목", "qty": 1, "unit_price": 1000, "amount": 1000}],
    "supply": 909,
    "vat": 91,
    "total": 1000,
    "payment": "카드",
    "status": "ok",
    "note": ""
  },
  {
    "file": "samples/다른파일.png",
    "date": null, "merchant": "상호", "items": [], "supply": null, "vat": null, "total": null, "payment": null,
    "status": "확인 필요",
    "note": "합계 부분이 가려져 금액을 읽을 수 없음"
  }
]
```

`items` 의 `qty`·`unit_price` 가 원본에 없으면(합계만 있는 품목) `qty: 1`, `unit_price` = `amount`.
